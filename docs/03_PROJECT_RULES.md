# Project Rules

## Objective

Keep AImetos secure, understandable, and inexpensive to operate over time.

## Rules

- Never commit credentials, secrets, customer data, or production exports.
- Prefer clear, boring solutions over clever abstractions.
- Document interfaces, ownership, failure modes, and rollback steps.
- Make changes small, testable, observable, and reversible.
- Remove duplication only when the replacement is simpler.

## Definition of done

A change is documented, validated, reviewable, and safe to roll back.
